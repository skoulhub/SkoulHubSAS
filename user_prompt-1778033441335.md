Build **SkoulHub** as a secure, production-ready **multi-tenant SaaS platform** with strict tenant isolation, role-based access control, and automatic tenant provisioning.

---

## 🏢 MULTI-TENANT ARCHITECTURE

* The system must support multiple schools (tenants)
* Each school (tenant) must have a unique identifier: `school_id` (tenant_id)
* All data (students, teachers, finance, reports, etc.) must be scoped to this `school_id`
* Enforce isolation using backend security (Row-Level Security)

---

## 🆔 AUTOMATIC TENANT ID ASSIGNMENT

* When a new school signs up (onboarding):

  * Automatically generate a **unique `school_id`**
  * Use a secure method (UUID recommended)
* This process must be:

  * Fully automatic (no manual input)
  * Collision-free (globally unique)
  * Stored in the schools/tenants table

---

## 🔄 ONBOARDING FLOW

1. User signs up (School Admin)
2. System creates a new tenant (school record)
3. Automatically generate `school_id`
4. Link the user to that `school_id`
5. Assign role: School Admin
6. Initialize default data (optional):

   * Sample classes
   * Basic settings

---

## 🔗 DATA LINKING RULE

* Every table must include `school_id`
* Every query must filter by `school_id`
* All relationships must enforce tenant ownership

---

## 🧠 GLOBAL VS TENANT SYSTEM

1. SaaS Admin Portal (Global)

* Has access to ALL tenants
* Can:

  * View and manage all schools
  * Track student counts
  * Manage billing (15,000 per student)
  * Handle onboarding and training

---

2. Tenant Portals (School-Level)

* All other users belong to a specific school
* Users MUST only access their own tenant data
* No cross-tenant access allowed

---

## 👥 ROLE-BASED ACCESS (WITHIN TENANT)

Roles:

* School Admin
* Head Teacher
* Teacher
* Parent
* Student (optional)
* Bursar / Accountant

---

🔐 PERMISSION RULES

* School Admin:
  Full control within their school

* Head Teacher:

  * Read access to all school data
  * Approves financial requests
  * Comments on student reports

* Teacher:

  * Access only assigned classes/students
  * Marks attendance
  * Enters results

* Parent:

  * Only sees their children
  * Views reports, payments, attendance

* Student:

  * Views own data only

* Bursar / Accountant:

  * Manages payments, expenses, payroll
  * Submits for approval

---

## ⚙️ SECURITY ENFORCEMENT

* Enforce all access at backend level
* Use Row-Level Security (RLS)
* Never rely only on frontend filtering
* Prevent cross-tenant data access at database level

---

## 🎯 GOAL

Ensure SkoulHub is:

* Secure (strict tenant isolation)
* Scalable (supports many schools)
* Automated (tenant creation handled seamlessly)
* Structured (clear separation between global admin and tenant roles)
